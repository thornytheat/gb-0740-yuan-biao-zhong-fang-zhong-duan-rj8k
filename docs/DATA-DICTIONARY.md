# 数据字典

| 字段 | 含义 | 约束 |
|---|---|---|
| `datasets[].id`, `revision` | 数据集和变换修订 | ASCII 字母、数字、下划线和短横，保留前导零；每数据集至多 12 条输入边。 |
| `datasets[].inputs[].dataset`, `lag` | 上游名与读取时差 | 当下游日为 D 时读取 `D−lag`；天数 0–7。依赖图须无环。 |
| `heads[].dataset`, `day`, `version`, `rows` | 当前分区指针及行数 | 分区由 `dataset@YYYY-MM-DD` 标识。当前快照每分区唯一。 |
| `changes[].version`, `previous`, `rows` | 源分区的新版本、预计当前版本、行数 | `previous=null` 代表期望新增。仅源表可登记直接变更。兼容旧 `count` 字段。 |
| `through` | 分区截止日 | 包含该日期，从最早受影响输入向下游传播，不触及截止之后的分区。每条变更回溯最多 31 日。 |

相同变更的重传计为重复。相同分区的候选版本或行数打架时全部隔离，保留行号。每个分区先计算最终应读哪些快照，按数据集拓扑序再按分区日排列。已阻断的计划不会被依赖者误当作有效输入，窗口内未受影响的依赖可复用当前快照。

新版本由下游数据集、规则修订、分区日和排序后的输入版本及行数共同计算 SHA-256。演示数据集执行拼接，各读入分区行数相加。数值使用整数，超出 JSON 常见安全整数范围的汇总或派生数按字符串输出。

写入演练先核验每个待写指针，再一次性生成新视图。回滚先核验仍持有演练发布版本，再逐项恢复原指针，新增分区则移除。任一指针陈旧时整组拒绝。该过程作用于清单中的副本，实际仓库的调度与执行另由值班系统负责。

受影响分区 = 待写 + 复用 + 阻断。输入行数 = 采信 + 隔离 + 重复。写入后的行数 = 原行数 + 待写分区行数增量。阻断保留原快照行数。批次绑定原始字节和规则版本，文件大小至多 300 KiB。

## M8 差额说明（可选字段 `baseline` / `arrivals`）

| 字段 | 含义 | 约束 |
|---|---|---|
| `baseline[].dataset/day/rows` | 分区基线行数 | 可选；缺省取当前指针。显式值必须与当前指针一致，否则 `VARIANCE_BASELINE` 拒绝 |
| `arrivals[].team` | 来源团队标识 | 与数据集同标识规则，责任方按团队归集 |
| `arrivals[].source_line`, `source_ref` | 来源原始报送行号与记录定位 | 必填，供来源团队按自己的原始记录复算 |
| `arrivals[].business_key`, `target_key` | 业务键与改键后的目标键 | 未改键时 `target_key` 可省略，默认取业务键 |
| `arrivals[].remapped`, `original_partition` | 是否改键、改键前所在分区 | 改键记录须带 `remapped=true` |
| `arrivals[].impact_rows` | 该记录对目标分区行数的带符号影响 | 支持全角千分位与负数；大整数按字符串输出 |
| `arrivals[].arrived_after_freeze` | 是否基线冻结后到达 | 迟到修订必须为 true，否则 `VARIANCE_EVIDENCE` |
| `arrivals[].kind` | 来源自报原因 | 仅作交叉校验；与系统按目标键复核结果不一致即拒绝 |

系统按「目标分区 + 目标键」分组复核客观原因，不信任自报：非改键单条=迟到修订（LATE_REVISION），非改键同键多条首条迟到、其余来源重复（DUPLICATE）；改键单条=改键合并（KEY_MERGE），改键后同键相撞=改键撞键重复（KEY_COLLISION）。分区差额 − 已解释合计 = 未解释余量（UNEXPLAINED），挂值班平台团队补数。

同一行在不同口径下原因码不变，只切换责任方：迟到修订/来源重复两口径均归来源团队；改键合并在平台口径归平台键治理团队、来源口径归来源团队；改键撞键重复两口径均归平台键治理团队且 `计入来源迟到=false`，避免来源团队被多记。占比按带符号基点（bp，1bp=0.01%）向零取整展示。差额合计必须等于 M6 的「行数变化」，守恒校验不通过则不出说明。

说明编号由计划编号与说明正文规范序列化的 SHA-256 派生；重放重试得到同一编号。账本 `variance_statements` 只追加，无更新/删除通道（改写请求返回 405），`variance_audit` 记录 ISSUE_CREATED / ISSUE_REUSED / GET 及流水哈希，旧说明可随时回查。
